# Example: Migrating ADP ClawAgent Exports to AgentKit Runtime

## Overview

This example shows how to migrate an application package exported from ADP / TCADP ClawAgent into a VeADK project that can be deployed to AgentKit Runtime.

An ADP / TCADP ClawAgent export package is not a Python project that can be published directly to AgentKit Runtime. Its application information, Agent instructions, model configuration, tool configuration, and runtime configuration are mainly stored in JSON files exported from the platform. For Agent projects generated by this type of low-code platform, you can combine the AgentKit Migration command with AgentKit Codex Sandbox to complete an automated migration: use `agentkit migrate any_input --framework any create` to create a migration task and submit the export package. The remote Codex Sandbox then analyzes the application configuration, Agent configuration, and visible behavior, and generates a VeADK project deployable to AgentKit Runtime.

The input for this example is a travel planning ClawAgent application. The source application is a local travel planning assistant for China. It contains travel materials for Beijing, Chengdu, and Hangzhou, budget judgment rules, and companion rules. The migration output is a VeADK project converted by Codex, and you can deploy this project directly to AgentKit Runtime.

This document guides you through export package preparation, remote migration task creation, result query and download, migration artifact inspection, and publishing to AgentKit Runtime with `agentkit release`.

## Core Features

This example covers the complete migration path from an ADP / TCADP ClawAgent export package to an AgentKit Runtime project:

- Read application metadata, Agent instructions, model configuration, tool configuration, and visible behavior from the ClawAgent export package.
- Convert a ClawAgent application into a VeADK / AgentKit Runtime project through the remote Codex Sandbox.
- Generate deployable configuration, runtime code, a migration report, and evaluation samples, with support for continuing to run `agentkit release`.
- Preserve capability boundary descriptions in the migrated artifacts for real-time data, external APIs, or real inventory query capabilities that do not exist in the source application. Do not fabricate external call results.

## Original Input

The input directory is `any_input/`, which contains a ClawAgent application package exported from the ADP / TCADP platform. To prepare it, select the target application in the platform application list and export it, download the ZIP file and unzip it, then place the entire extracted export directory into `any_input/`.

The input directory in this example is:

```bash
any_input/

        ├── app_variable.json
        ├── base_config.json
        └── metadata.json
```

The source application information for migration is:

- Project name: `travel-planner-example`
- Project type: TCADP / ADP ClawAgent export package
- Agent name: `travel-planner-main`

## Directory Structure

```bash
claw/
├── .env.example       # Environment variable example
├── README.md          # Chinese documentation
├── any_input/         # Input directory for the ADP / TCADP ClawAgent export package
```

All subsequent commands are executed in the `ADP/claw/` directory. `any_input/` is the source project input directory. `--output ../any_output` is resolved relative to `any_input/`, and the migration artifacts are written to the `any_output/` directory at the same level as `any_input/`.

## Start Remote Migration

### Check the AgentKit CLI Version

First make sure that the TypeScript version of the AgentKit CLI is installed locally, and that its version is no lower than `0.51.1`:

```bash
agentkit -v
```

Or:

```bash
ak -v
```

If it is not installed, or if the version is lower than `0.51.1`, install the TypeScript version of the AgentKit CLI with:

```bash
curl https://agentkit-cli.tos-cn-beijing.volces.com/install.sh | sh
```

> The migration command is recommended to use the TypeScript AgentKit CLI entry point `ak`, to avoid command-name conflicts with the `agentkit` command from a Python `uv` environment or `agentkit-python-sdk`. `ak` is configured automatically by the installation script and requires no extra steps.

### Environment Preparation

In the `ADP/claw/` directory, copy `.env.example` to `.env`, then fill in the environment variables required for migration and deployment.

Before running, the AgentKit CLI automatically loads the `.env` file in the current execution directory. You do not need to manually run `source .env`. Therefore, you can write the environment variables directly into `.env` and avoid importing them manually each time. `CODEX_MIGRATE_MODEL_API_KEY` is used for the remote Codex Sandbox migration task, and `MODEL_AGENT_API_KEY` is used by the migrated application runtime to call the model.

Note: `--codex-api-key-env` and `--model-api-key-env` take environment variable key names. The CLI reads the corresponding real keys from `.env`. The `--codex-model`, `--model-id`, and `--model-base-url` parameters need actual values.

Volcengine:

```bash
BYTEPLUS_ACCESS_KEY=""
BYTEPLUS_SECRET_KEY=""

CODEX_MODEL_AGENT_NAME=""
CODEX_MIGRATE_MODEL_API_KEY=""

MODEL_AGENT_NAME=""
MODEL_AGENT_API_BASE="https://ark.cn-beijing.volces.com/api/v3"
MODEL_AGENT_API_KEY=""
```

BytePlus platform:

If you use the BytePlus platform, fill in the BytePlus AK/SK and model access configuration. In `.env`, replace the Volcengine account variables with `BYTEPLUS_ACCESS_KEY` / `BYTEPLUS_SECRET_KEY`, and set `CLOUD_PROVIDER=byteplus` and `BYTEPLUS_REGION`.

```bash
BYTEPLUS_ACCESS_KEY=""
BYTEPLUS_SECRET_KEY=""
CLOUD_PROVIDER=byteplus
BYTEPLUS_REGION=ap-southeast-1

CODEX_MODEL_AGENT_NAME=""
CODEX_MIGRATE_MODEL_API_KEY=""

MODEL_AGENT_NAME=""
MODEL_AGENT_API_BASE=""
MODEL_AGENT_API_KEY=""
```

### Create a Migration Task

`create` submits `any_input/` to the remote Codex Sandbox for migration. `--output ../any_output` is resolved relative to `any_input/`, and the final artifacts are written to `ADP/claw/any_output/`.

```bash
cd <project_dir>/ADP/claw

agentkit migrate any_input --framework any create --name any-test --output ../any_output \
  --codex-model <codex-model-name> \
  --codex-api-key-env CODEX_MIGRATE_MODEL_API_KEY \
  --model-id <VeADK-model-name> \
  --model-base-url <model-base-url-required-by-VeADK> \
  --model-api-key-env MODEL_AGENT_API_KEY
```

Equivalent command using `ak`:

```bash
cd <project_dir>/ADP/claw

ak migrate any_input --framework any create --name any-test --output ../any_output \
  --codex-model ep-20260601142014-7hztz \
  --codex-api-key-env CODEX_MIGRATE_MODEL_API_KEY \
  --model-id ep-20260601142014-7hztz \
  --model-base-url "https://ark.cn-beijing.volces.com/api/v3" \
  --model-api-key-env MODEL_AGENT_API_KEY
```

After creation succeeds, the command returns a `job_id`. The actual task record for this example is stored in `any_input/.agentkit/migrate/jobs/<job_id>.json`, and the migration result can be downloaded to `any_output/`.

## Query and Download Results

Query the task status and download the final artifacts:

```bash
agentkit migrate any_input --framework any status --job-id <job_id>
```

Equivalent `ak` command:

```bash
ak migrate any_input --framework any status --job-id <job_id>
```

You can also use the positional argument form:

```bash
agentkit migrate any_input --framework any status <job_id>
```

Equivalent `ak` command:

```bash
ak migrate any_input --framework any status <job_id>
```

View local migration task records:

```bash
agentkit migrate any_input --framework any list
```

Equivalent `ak` command:

```bash
ak migrate any_input --framework any list
```

## Optional: Local Debugging for the VeADK Project

Before deploying to AgentKit Runtime, you can enter `any_output/` to inspect the migration artifacts. It is recommended to focus on:

- `assistant/agent.py`: The migrated VeADK agent, including the travel planning assistant persona, city materials, budget judgment rules, companion rules, and capability boundary descriptions.
- `.agentkit/agentkit.yaml`: AgentKit Runtime deployment configuration, including model, resource specifications, environment variables, and APMPlus configuration.
- `migration_metadata.json`: Source application information, preserved behavior, degraded behavior, and evaluation suite description.
- `eval/cases.json` and `eval/rubric.md`: Behavior validation samples and evaluation criteria for the migrated application.

The migration artifacts in this example have passed the static checks recorded in `convert_report.md`, including Python compilation, required file existence, `assistant.agent.root_agent` import, `main.app` import, and AgentKit configuration checks.

## AgentKit Deployment

After migration is complete, enter the output directory, confirm that `.agentkit/agentkit.yaml` is configured correctly, and then run:

```bash
cd any_output
agentkit release
```

Equivalent `ak` command:

```bash
cd any_output
ak release
```

## Parameter Description

- `--framework any`: Use general agentic migration.
- `create`: Create a remote migration task.
- `status`: Query the task and download results.
- `list`: View local records under `any_input/.agentkit/migrate/jobs/`.
- `--codex-model`: Specify the model used by the remote Codex Sandbox. Pass the actual model name.
- `--codex-api-key-env`: Specify the environment variable name from which the remote Codex Sandbox reads the model key.
- `--model-id`: Specify the business model used by the migrated project at runtime. Pass the actual model name.
- `--model-base-url`: Specify the OpenAI-compatible endpoint for the business model. Pass the actual base URL.
- `--model-api-key-env`: Specify the environment variable name for the business model key. If omitted, the default is `MODEL_AGENT_API_KEY`.

## FAQ

- Will the migration command rewrite the source export package in `any_input/`?

  No. The migration task uploads the source export package as input for analysis, and writes the generated AgentKit Runtime project to the directory specified by `--output`.
