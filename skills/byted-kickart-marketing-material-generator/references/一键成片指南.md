# 一键成片工具指南

## 触发场景

当用户需要基于抖店/抖音商品链接或商品 ID，结合图片、视频等自定义素材，生成商品营销短视频或一键成片内容时使用本工具。典型说法包括「一键成片」「生成商品视频」「生成营销视频」「用这个商品链接做视频」「帮我把这些素材做成短视频」。

## 执行流程

### Phase 0: 初始化（提交前确认）

在执行一键成片任务前，必须依次引导用户完成以下准备工作。

> 🚨 **核心规则：所有步骤必须逐一询问，Agent 不得私自跳过任何一步。**
> - 必填步骤：用户必须提供有效值才能继续。
> - 条件必传步骤：至少满足条件组合中的一个有效值才能继续。
> - 可选步骤：必须主动提示用户可以输入值或选择默认值，用户可以回复「跳过」「默认」「不填」「不需要」使用默认值或跳过；Agent 绝对不能在未询问用户的情况下自行跳过可选参数。
> - 每完成一步，必须明确记录状态已流转至下一步。
> - Agent不要擅自合并、优化、篡改任何一步，必须严格按照顺序执行。

**📋 信息收集总览**：创建一键成片视频需要依次确认以下信息，请准备好相关素材：
> 1. **素材与商品信息**（条件必传，至少一项）：商品链接/商品ID/图片素材/视频素材
> 2. **视频时长**（必填）：支持15/30/45/60秒
> 3. **画幅比例**（可选，默认9:16）
> 4. **语言**（可选，默认zh中文）
> 5. **视频用途**（可选，默认好物推荐）
> 6. **创意指令**（可选）
> 7. **字幕设置**（可选，默认开启）
> 8. **字幕擦除**（可选，默认关闭）
> 9. **AI 明水印**（可选，默认关闭）
>
> 模板固定为「商品介绍视频（seedance2.5-720p）」，template_id=978755842。

1. **素材与商品信息获取（条件必传，至少提供一项）**：依次询问用户以下四项信息，四项中至少有一项非空才能继续：
   - **① 商品链接**：向用户发送话术：「请提供抖店/抖音商品链接（如 https://haohuo.jinritemai.com/xxx），如不提供可回复「跳过」或「不提供」。」根据用户提供内容映射为 `--product-url` 参数。用户回复「跳过」「不提供」「无」等则不传。
   - **② 商品ID**：向用户发送话术：「请提供抖店商品ID（纯数字，如 3702335710741791054），如不提供可回复「跳过」或「不提供」。」根据用户提供内容映射为 `--product-id` 参数。用户回复「跳过」「不提供」「无」等则不传。
   - **③ 图片素材**：向用户发送话术：「请提供用于成片的图片素材：本地文件支持 JPEG、PNG，单张 ≤8MB；也可提供公网图片 URL。如不提供可回复「无图片」。」
     - 如果用户提供图片：本地图片校验文件存在、绝对路径、JPEG/PNG 格式和 ≤8MB 限制；公网图片校验为有效 HTTP(S) URL。按用户提供顺序整理为 `--user-images` 的值，不预先上传。
   - **④ 视频素材**：向用户发送话术：「请提供用于成片的视频素材：本地文件支持 MP4、MOV，单个 ≤50MB；也可提供公网视频 URL。如不提供可回复「无视频」。」
     - 如果用户提供视频：阅读 `references/视频参考指南.md`。本地视频完成基础校验后保留绝对路径，公网视频保留有效 HTTP(S) URL，按用户提供顺序整理为 `--user-videos` 的值，不预先上传。
   - **条件校验**：完成以上四项询问后，必须校验 `--product-url`、`--product-id`、`--user-images`、`--user-videos` 四项中至少有一项非空。若四项均为空，必须停止并请用户至少提供其中一项，不允许提交任务。
   无论用户选择哪种组合方式，完成后必须明确记录状态已流转至下一步。

2. **视频时长确认（必填）**：向用户发送话术：「请选择视频时长：15、30、45、60 秒。」根据用户选择映射为 `--duration`。如果用户输入 `10` 或其他值，必须说明接口真实验证中 `10` 返回 `DurationEnumError`，请改选 `15/30/45/60`。成功确认后，必须明确记录状态已流转至下一步。

3. **画幅比例确认（可选，必须询问）**：向用户发送话术：「请选择视频比例，支持 9:16、16:9、3:4、4:3、1:1；默认使用 9:16。你也可以回复默认。」映射为 `--aspect-ratio`。用户回复「默认」「跳过」「不填」则使用默认值 9:16。成功确认后，必须明确记录状态已流转至下一步。

4. **语言确认（可选，必须询问）**：向用户发送话术：「请选择视频语言：zh（中文）、en（英文）、pt-br（巴西葡萄牙语）；默认使用 zh。你也可以回复默认。」映射为 `--language`。用户回复「默认」「跳过」「不填」则使用默认值 zh。成功确认后，必须明确记录状态已流转至下一步。

5. **视频用途确认（可选，必须询问）**：向用户发送话术：「请选择视频用途，商品介绍视频支持品牌广告、好物推荐、剧情演绎、测评对比、日常Vlog、开箱直拍型（仅海外）；默认使用好物推荐。你也可以回复默认。」映射为 `--purpose`。用户回复「默认」「跳过」「不填」则使用默认值好物推荐。成功确认后，必须明确记录状态已流转至下一步。

6. **创意指令确认（可选，必须询问）**：向用户发送话术：「请提供创意指令，用来描述视频核心内容、风格和卖点，最长 5000 字；不提供可回复跳过。」映射为 `--prompt`。用户回复「跳过」「默认」「不填」则不传该参数。成功确认后，必须明确记录状态已流转至下一步。

7. **字幕设置确认（可选，必须询问）**：向用户发送话术：「是否在生成视频中添加硬字幕？默认开启。回复开启/关闭/默认即可。」映射为 `--nle-subtitle-enabled`。用户回复「默认」则设置为 `true`（添加字幕）。成功确认后，必须明确记录状态已流转至下一步。

8. **字幕擦除设置确认（可选，必须询问）**：向用户发送话术：「是否在分镜渲染阶段尝试擦除视频底部字幕？默认关闭。回复开启/关闭/默认即可。」映射为 `--use-subtitle-erasure`。用户回复「默认」「跳过」则设置为 `false`（不开启）。成功确认后，必须明确记录状态已流转至下一步。

9. **AI 明水印确认（可选，必须询问）**：向用户发送话术：「是否添加“AI生成”明水印？默认关闭。回复开启/关闭/默认即可。」映射为 `--watermark`。用户回复「默认」「跳过」则设置为 `false`。成功确认后，必须明确记录状态已流转至下一步。

10. **展示成片信息（强制不可跳过）**：在收集齐上述所有参数（包括必填、条件必传和可选）后、准备正式提交任务之前，必须先汇总所有已确认的参数信息，按照以下格式向用户展示即将生成的成片信息，询问用户是否符合预期。

> 🚨 **强制要求**：此步骤不可因为鉴权失败重试、参数调整、会话恢复或其他任何原因跳过。即使用户之前已确认过，每次提交新任务前都必须重新展示。

**播报模板示例（严格使用普通正文格式展示，保留换行，具体内容需从上文已收集的参数中提取填充）：**
```text
视频成片信息如下，请进行确认：
- 模板：商品介绍视频（seedance2.5-720p）
- 商品链接：[用户提供的商品链接，或"未提供"]
- 商品ID：[用户提供的商品ID，或"未提供"]
- 成片时长：[用户选择的时长，如 15s]
- 用户素材：[图片 X 张 / 视频 X 个，如 图片 3 张；若均未提供则显示"未提供"]
- 视频比例：[用户选择的比例或默认值，如 9:16（竖屏）]
- 语种：[用户选择的语言或默认值，如 中文(zh)]
- 视频分类：[用户选择的分类或默认值，如 好物推荐]
- 字幕：[添加/不添加，默认添加]
- 字幕擦除：[开启/关闭，默认关闭]
- AI明水印：[添加/不添加，默认不添加]
- 创意指令：[用户输入的内容摘要，或"未提供"]

👉 请确认以上成片信息是否符合您的预期？
```

11. **二次确认与合规提示（强制不可跳过）**：当用户明确回复成片信息符合预期后，必须进行二次确认，明确告知扣费风险及合规要求。等待用户明确回复确认或同意后，才可进入提交任务（Phase 1）环节。

> 🚨 **强制要求**：此步骤不可因为鉴权失败重试、参数调整、会话恢复或其他任何原因跳过。即使用户之前已确认过，每次提交新任务前都必须重新进行二次确认。

**二次确认播报模板（必须以普通 Markdown 正文输出，不得放入代码块）：**

> ⚠️ 本次任务将会消耗创点，任务发起后创点消耗不可退还。
>
> 请确认您已经阅读并同意了 [合规承诺函](https://www.volcengine.com/docs/6664/2369383?lang=zh)，且您有权使用提交的所有信息及内容，上传的素材均已获得合法授权。

发送该确认消息前必须检查：

- `[合规承诺函](https://www.volcengine.com/docs/6664/2369383?lang=zh)` 完整存在。
- 链接未被反引号或围栏代码块包裹，能够由 Markdown 渲染为可点击超链接。
- 不得改写为纯文本标题、裸 URL，也不得省略链接。
- 链接检查通过且用户明确确认后，才能进入 Phase 1。


### Phase 1: 提交任务

用户确认生成后执行以下操作：

1. 读取 `references/CLI前置校验指南.md`，确认 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli` 可用且 OAuth 登录态有效；否则按前置指南完成登录或终止操作。
2. 首次调用或参数不确定时执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_marketing_task_v2 --help`，根据 Phase 0 收集的信息构造 CLI 参数，不得猜测帮助中未声明的选项。
3. 参数映射原则：
   - 条件必传：`--product-url`、`--product-id`、`--user-images`、`--user-videos` 至少提供一项。
   - 必填：`--duration`，传 `15`、`30`、`45` 或 `60`。
   - 可选：`--template-id`、`--aspect-ratio`、`--language`、`--purpose`、`--prompt`、`--nle-subtitle-enabled`、`--use-subtitle-erasure`、`--extra-params`、`--watermark`。
   - 模板固定为 `978755842`，显式传入 `--template-id 978755842`。
   - 本地素材完成格式、大小、文件存在性和绝对路径校验后，通过 `--user-images` 或 `--user-videos` 直接传入绝对路径，由 `submit_marketing_task_v2` 自动上传并转换为 URL。
   - 多素材参数按命令 `--help` 声明的方式传入并保持用户提供顺序，每个路径或 URL 作为独立参数安全传递。
   - 布尔选项按 CLI `--help` 声明的形式传入，不得自行猜测开关语法。
   - 用户明确回复“跳过”或“不填”的可选参数不传；用户选择“默认”时按 CLI 默认行为处理。
4. 执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_marketing_task_v2`。基础命令示例：

```bash
npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_marketing_task_v2 \
  --template-id 978755842 \
  --duration 15 \
  --product-url https://example.com/item \
  --user-images /absolute/path/to/product.jpg \
  --aspect-ratio 9:16 \
  --language zh
```

实际执行时仅传用户确认过的参数；路径、URL、提示词不得通过未经转义的 shell 字符串拼接。
5. 命令退出码为 `0` 时解析 stdout JSON，提取 `task_id`、`request_id`、`request_body` 和 `raw`，立即将任务 ID、请求 ID、任务类型、提交时间、当前会话 ID和参数摘要保存到会话上下文。
6. `submit_marketing_task_v2` 会创建付费异步任务，不保证幂等，**任何失败场景均禁止自动重试提交命令**。命令非零退出或未获得完整成功响应时，读取并脱敏 stdout/stderr，并按以下规则处理：

   - **能够证明请求未发送**：仅限本地参数校验失败、CLI 进程未成功启动、OAuth 前置校验失败等明确发生在网络请求前的错误。修复问题后不得直接提交，必须返回 Phase 0 第 10、11 步，重新展示全部成片信息并取得用户二次确认。
   - **无法确认请求是否已受理**：包括网络中断、请求超时、响应解析失败、响应落盘失败、进程异常退出，或任何不能证明请求未发送的情况。禁止再次执行提交命令；若输出中存在 `task_id`，按 `references/任务查询指南.md` 查询该任务；若仅存在 `request_id`，记录并反馈用户用于人工排查；两者均不存在时，明确告知用户任务状态未知和重复提交可能重复扣费，等待用户核实后再决定，不得擅自重提。
   - **服务端明确拒绝且未创建任务**：向用户说明错误码和修正方案。需要修改参数时返回 Phase 0 对应信息收集步骤，修改完成后重新执行第 10、11 步；即使参数未变化，再次提交前也必须重新展示全部成片信息并取得二次确认。
   - 只有 CLI 或接口明确提供并实际使用幂等键时，才能依据其契约安全重放；不得自行假设 `request_id` 具有幂等能力。

### Phase 2: 提交后回复

提交任务成功后，必须向用户回复：

```text
一键成片任务已提交成功！
任务 ID：<task_id>
当前任务会继续在后台生成。你可以稍后说「查询进度」或提供任务 ID 查询结果。
```

同时必须将任务 ID、任务类型、提交时间、当前会话 ID 和参数摘要持久化到会话上下文，便于后续使用 `references/任务查询指南.md` 查询。

### Phase 3: 查询与结果处理

当用户查询进度时，读取 `references/任务查询指南.md` 并执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli query_task_v2 --task-id <ID> --source kickart_ai_material --auto-publish true`。禁止在提交阶段主动轮询，也禁止直接请求 OpenAPI。任务成功后，从 stdout JSON 中提取最终视频 URL 并反馈用户。
