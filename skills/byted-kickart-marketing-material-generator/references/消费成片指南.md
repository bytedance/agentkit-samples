# Kickart 消费成片生成工具

## 触发场景
当用户需要将故事板转换为成片视频，提到「消费成片」、「生成成片」、「故事板生成视频」、「提交成片任务」时使用本工具。

## 执行流程
### Phase 0: 初始化（提交前确认）
1. 确认获取到故事板 JSON 文件路径 `input`
2. 确认用户选择的故事板编号 `storyboard` 为 0-4 范围内的合法值（注意：JSON 文件中故事板编号从 0 开始计数，用户说"第 N 个"通常对应编号 N-1）
3. 通过 `sessions_list` 获取当前会话的 `sessionId`：
   - 直接调用 `sessions_list` 获取当前会话，不需要添加任何额外参数
   - **必须从返回结果中获取有效的 sessionId，禁止任何构造、推理、fallback 等行为**
4. 从入站上下文提取完整 metadata：
   - `sender`：直接使用入站上下文中提供的 untrusted metadata 完整 JSON
   - `chat_type`：从入站元信息中读取，默认为 `direct`
   - `channel`：从入站元信息中读取，如 `feishu`/`webchat`/`discord`等
   - `chat_id`：从入站元信息中读取，如 `user:ou_22070ce404148983b57582d681963872`
   - **必须从返回结果中获取有效的 channel 和 chat_id，禁止任何构造、推理、fallback 等行为**
5. 构造 session 参数（JSON 字符串）：`{"sessionId": "<sessionId>"}`，必须是完整合法 JSON
6. 构造 metadata 参数（完整 JSON 字符串，确保所有必填字段都存在）：
   ```json
   {
     "sender": <完整 sender 元信息对象>,
     "chat_type": "<direct/group>",
     "chat_id": "<会话 ID>",
     "channel": "<当前渠道，如 feishu/webchat>"
   }
   ```
   - 注意：sender 必须保留原始 JSON 结构，不要拆解或修改
   - 必须确保 metadata 是完整合法的 JSON 字符串，供工具内部 json.loads 解析
7. 向用户明确告知「创点扣除后不可退回、重复提交将产生额外费用」，等待用户回复「确认生成」后再进入下一步。

### Phase 1: 提交任务
用户确认生成后执行以下操作：
1. 确保输出目录存在：
   ```bash
   mkdir -p /tmp/kickart/output
   ```
2. 生成唯一输出文件名：
   ```bash
   VIDEO_FILE="/tmp/kickart/output/video_$(date +%s%N | cut -b1-13)_$((RANDOM%900000+100000)).json"
   ```
3. 提交生成任务（注意 session 和 metadata 参数必须是合法 JSON 字符串，不要嵌套字典）：
   ```bash
   python consumption.py submit --storyboard <storyboard> --input <input> --output "$VIDEO_FILE" --session '<session 参数 JSON 字符串>' --metadata '<metadata 参数 JSON 字符串>'
   ```
4. 如果提交返回错误码，根据错误码补充缺失的参数后重试，最多重试 3 次

### Phase 2: 提交后回复
从提交结果中提取 code 为 0 时返回的任务 ID，按照以下模板回复用户：
```txt
✅ 成片生成任务已按标准规范提交成功，任务 ID:<任务 ID>
⚠️ 请勿重复提交相同任务，避免产生额外创点消费
⚠️ 后台每 6 秒自动查询进度，生成完成后会第一时间通知您，请耐心等待~ 🦞
```
如果提交失败，按照以下模板回复：
```txt
❌ 成片生成任务提交失败
- 错误信息:<返回的 message 字段内容>
- 我将自动重试，无需您操作~ 🦞
```
重试 3 次仍失败则提示用户手动确认参数

```

- 错误码:<错误码>
- 处理建议:<匹配 SKILL 错误规范的处理建议>

```
