# 素材上传指南

本指南仅适用于用户明确要求将素材独立上传到 KickArt、创建媒资或保存到素材库的场景。生成任务中的本地素材直接传给 `submit_marketing_task_v2`，不得读取或执行本指南。

## 目的与适用场景

本指南的主要目的是**上传本地图片或视频到媒体服务，并获取可用的媒资 ID 和 URL**。

## 输入与参数

本指南的所有本地素材操作都通过 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli material_pipeline_v2` 执行。

- **`--file-path`**：必填，必须是 CLI 进程可读取的 JPEG、PNG、MP4 或 MOV 文件绝对路径。
- 素材类型由扩展名推断，无需为流水线命令额外传类型。
- **大小限制**：图片不超过 8MB，视频不超过 50MB。

## 执行流程

Agent 在使用此指南时，应遵循以下流程：

1. **识别输入类型**：
   - 用户直接上传本地文件：使用系统提供的绝对路径执行 `material_pipeline_v2`。
   - 用户提供公网 URL，且后续 `submit_marketing_task_v2` 支持对应 URL 字段：直接保留 URL，不必先上传。
   - 用户明确要求将公网素材保存为 KickArt 媒资：先获得 CLI 进程可读取的本地文件，再执行 `material_pipeline_v2`。

2. **上传素材**：
   - 图片或视频均执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli material_pipeline_v2 --file-path <绝对路径>`。
   - 命令退出码为 `0` 时解析 stdout JSON，从 `created.media_id` 提取媒资 ID，从 `origin_url` 提取原始下载 URL。
   - `origin_url` 为 `null` 时明确告知用户媒资已创建但暂未取得原始下载 URL，不得虚构 URL。
   - 将会话 ID、素材类型、`media_id`、URL 和上传时间保存到当前会话上下文。

3. **向用户反馈**：
   - 使用消息模板向用户反馈上传结果。
   - 上传失败时明确说明失败文件、错误码、原因和可执行解决方案。

## CLI 调用示例

```bash
npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli material_pipeline_v2 \
  --file-path /absolute/path/to/file.mp4
```

**返回结果示例**：
```json
{
  "upload": {"id": "object-id", "file_name": "file.mp4", "etag": "...", "size": 1024},
  "created": {"media_id": "media-id", "media_store_id": "store-id"},
  "medias": [],
  "origin_url": "https://example.com/material.mp4"
}
```

## 注意事项

- **文件格式**：仅支持 JPEG、PNG、MP4、MOV。
- **文件大小**：图片不超过 8MB，视频不超过 50MB。
- **文件路径**：必须提供文件的绝对路径。
- **调用限制**：始终通过 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli` 调用固定版本；npm exec 获取包或启动 CLI 失败时，按 `CLI前置校验指南.md` 反馈错误并终止操作。
- **错误结果**：命令非零退出时读取 stderr，先过滤敏感信息再反馈，不得把错误输出当成成功 JSON。
