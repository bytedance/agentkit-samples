# 视频参考指南

## 目的与适用场景
当用户意图进行「一键成片」或主动提供参考视频时，使用本指南引导用户提供并校验参考视频，最终获取可直接传给 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_marketing_task_v2` 的本地绝对路径或公网 URL。

## 支持的输入方式
- 支持用户提供有效的**视频链接**。
- 支持用户**本地上传**视频文件。
- **不支持**选择 SAAS 资产库内视频。

## 视频规格要求
- **格式**：仅支持 `MP4` 或 `MOV`。
- **大小**：`≤50MB`。
- **时长**：`>5s` 且 `≤60s`。
- **分辨率**：`≥480p`。
- **比例**：支持 `9:16`, `16:9`, `3:4`, `4:3`, `1:1`。

## 交互方式与话术规范（强制遵守）
1. **引导提供视频**：
   当用户表达了一键成片的意图，但尚未提供参考视频时，必须按照以下话术引导：
   > 好的，我帮你创建一键成片项目。请先提供 参考视频：可以发我视频链接，或上传 MP4/MOV 文件（>5s 且 ≤60s、≤50MB、≥480p）

2. **错误/超限提示**：
   如果用户上传的视频不符合规格要求（工具返回错误），必须根据错误信息明确指出具体超限的数值，并引导用户重新提供。例如：
   > 这条视频 大小 80MB 超过 50MB 限制，请压缩或换一条再发我
   *(注意：请根据实际的超限指标（如时长、分辨率等）灵活替换上述模板中的字段)*

## 视频处理流程
用户提供视频后，按输入类型获取可供 `submit_marketing_task_v2` 使用的本地绝对路径或公网 URL：

### 步骤1：识别输入

- **用户提供公网视频 URL**：校验 URL 使用 HTTP(S) 协议并保留原始 URL，无需下载或上传。
- **用户上传本地视频文件**：获取 CLI 进程可读取的文件绝对路径。

### 步骤2：基础校验

本地文件不预先调用素材上传工具。提交前至少校验：

- 路径是 CLI 进程可读取的绝对路径，且文件存在。
- 扩展名为 `.mp4` 或 `.mov`。
- 文件大小不超过 50MB。
- 能够获取元数据时，继续校验时长 >5s 且 ≤60s、分辨率 ≥480p，比例属于 `9:16`、`16:9`、`3:4`、`4:3`、`1:1`。
- 无法在本地确认时长、分辨率或比例等元数据时保留该素材，将对应指标明确标记为“待服务端校验”，由 `submit_marketing_task_v2` 做最终服务端校验；不得声称已通过无法执行的校验。

### 步骤3：提取并保留结果

- 本地文件保留绝对路径，公网素材保留原始 URL。
- 多个视频按用户提供顺序组成字符串数组。
- 执行 `submit_marketing_task_v2` 时，通过 `--user-videos` 传入素材，具体多值语法以 `--help` 为准，由 CLI 自动上传本地文件并转换为 URL。
- 在会话上下文中保存输入来源、路径或 URL、已确认的素材规格和校验状态。

### 步骤4：向用户反馈
素材通过可执行的基础校验后，**必须**使用以下模板向用户反馈结果。
**严格要求**：必须使用普通正文格式展示，绝不可使用加粗语法（`**`），并且必须严格保留每一行的换行符！

## 📤 返回消息模板（强制遵守）

```text
✅ 参考视频已接收并通过基础校验
📁 输入来源：[本地文件/公网URL]
📍 素材位置：[仅展示文件名或脱敏后的URL，不泄露不必要的本地目录信息]
📝 校验结果：[格式、大小，以及实际能够确认的分辨率、时长、比例]
🔎 元数据校验状态：[已完成；或列出无法读取的指标并明确标记“待服务端校验”]
```

基础校验失败时明确指出失败文件、实际值、限制和修复建议。基础校验通过后不执行 `material_pipeline_v2`，待提交一键成片任务时由 `submit_marketing_task_v2` 自动完成本地素材上传。
