# 火山引擎鉴权操作指南
## 用途说明
本指南用于指导 agent 完成火山引擎 API 调用前的身份鉴权校验，确保 ACCESS_KEY_ID/SECRET_ACCESS_KEY（访问密钥）配置正确可用。

---

## 🚀 鉴权操作流程（必须严格按顺序执行）
### 步骤 1：执行环境变量检查命令
直接运行以下命令，检查鉴权配置：
```bash
echo "ACCESS_KEY_ID: $ACCESS_KEY_ID" && echo "SECRET_ACCESS_KEY: $SECRET_ACCESS_KEY"
```

### 步骤 2：判断鉴权结果
1. **鉴权通过**：如果 `ACCESS_KEY_ID` 和 `SECRET_ACCESS_KEY` 均为非空值，鉴权通过，可使用 AK/SK 签名方式调用接口
2. **鉴权不通过**：若不满足上述条件，说明未配置或配置无效，进入「未配置引导流程」

---

## ❌ 未配置时的引导方案
1. 引导用户直接在聊天中发送 ACCESS_KEY_ID/SECRET_ACCESS_KEY 内容：
   > 直接在此处发送您的 Access Key ID 和 Secret Access Key，我会帮您完成临时环境变量配置
2. 收到用户发送的 ACCESS_KEY_ID/SECRET_ACCESS_KEY 后，Agent 需要在**内存中临时记住**这两个值。
3. 配置完成后告知用户：
   > 已收到您的 ACCESS_KEY_ID/SECRET_ACCESS_KEY，将在本次会话的指令执行中临时使用，不会持久化存储，请放心使用
4. **安全调用规范（独立进程注入）**：由于每次底层指令执行都是在一个全新的 Shell 进程中，不共享环境变量，因此**不能仅执行一次 `export`**。后续**每一次**涉及 AK/SK 的业务指令，Agent 都必须在执行该指令时**再次进行内联 `export`**（例如：`export ACCESS_KEY_ID="真实明文" && export SECRET_ACCESS_KEY="真实明文" && ./业务脚本.sh`）。
   **关键注意**：在底层执行时，**必须使用用户提供的真实明文值**注入环境变量，绝对不能替换为 `***`，否则会导致鉴权失败！同时，**绝对禁止**将明文密钥直接拼接为业务脚本的普通命令行参数，必须通过环境变量传递。
