# 抖音/短视频爆款视频裂变、克隆工具指南

## 触发场景
当用户提及"爆款裂变"，或表达希望参考某热门视频的风格、制作风格类似内容的等价意图时使用本技能。

## 执行流程
### Phase 0: 初始化（提交前确认）
在执行爆款裂变任务前，必须依次引导用户完成以下准备工作。

> 🚨 **核心规则：所有步骤必须逐一询问，Agent 不得私自跳过任何一步。**
> - 必填步骤：用户必须提供有效值才能继续。
> - 可选步骤：Agent **必须**主动提示用户可以输入值或选择默认值，用户可以通过回复"跳过"、"默认"、"不填"、"不需要"等方式使用默认值或跳过。但 **Agent 绝对不能在未询问用户的情况下自行决定跳过可选参数。**
> - 每完成一步，必须明确记录状态已流转至下一步。

**📋 信息收集总览**：创建爆款裂变视频需要依次确认以下信息，请准备好相关素材：
> 1. **参考视频**（必填）：视频链接或上传 MP4/MOV 文件
> 2. **商品信息**（必填，三选一）：抖店/抖音商品链接 / 商品ID / 商品图片（1-10张）
> 3. **语言设置**（必填）：成片语种，默认中文
> 4. **角色图片**（可选）：自定义数字人形象，1-3张
> 5. **场景图片**（可选）：场景参考图，最多3张
> 6. **创意提示词**（可选）：自定义创意策略或爆点描述
> 7. **字幕设置**（可选）：是否添加硬字幕，默认添加
> 8. **字幕擦除**（可选）：是否擦除模型生成字幕，默认关闭
> 9. **AI 明水印**（可选）：默认关闭


1. **参考视频获取（必填）**：向用户发送话术："好的，我帮你创建爆款克隆项目。请先提供参考视频：可以发我视频链接，或上传 MP4/MOV 文件（≤60s、≤50MB、≥480p，支持 9:16/16:9/3:4/4:3/1:1）"。然后阅读 `references/视频参考指南.md`。公网 URL 或校验通过的本地绝对路径映射为 `--ref-video`，不预先上传。成功获取后，必须明确记录状态已流转至下一步。

2. **商品信息获取（必填，三选一）**：参考视频获取成功后，向用户发送话术："接下来请提供商品信息，以下三种方式任选其一即可：\n① 抖店/抖音商品链接（可以是商品详情链接，也可以是带商品信息的抖音分享链接）\n② 抖店/抖音商品ID（纯数字）\n③ 商品图片（1-10张，本地文件支持 JPEG/PNG、单张≤8MB，也可提供公网 URL）"。根据用户提供的内容，分别映射为 `--product-url`、`--product-id` 或 `--product-images`。本地商品图片校验文件存在、绝对路径、格式和大小后直接保留路径，公网图片保留有效 URL，所有图片按原顺序传递，不预先上传。其中商品链接能否被解析以 `submit_viral_task_v2` 的返回结果为准。**三项必须至少提供一个非空值**，否则无法提交任务。

3. **语言设置确认（必填）**：向用户发送话术："请问成片视频需要使用什么语言？支持以下选项：\n① 中文(zh)\n② 英文(en)\n③ 英语-美国(en-us)\n④ 巴西葡萄牙语(pt-br)\n⑤ 日语(ja)\n⑥ 西班牙语-墨西哥(es-mx)\n⑦ 印尼语(id)\n⑧ 马来语(ms)\n⑨ 他加禄语(tl)\n请回复序号或语言代号，默认使用中文(zh)。"根据用户选择设置 `--language`。用户回复"默认"则使用 `zh`。成功确认后，必须明确记录状态已流转至下一步。

4. **角色图片获取（可选，必须询问）**：向用户发送话术："是否需要自定义角色/模特图片？可上传 1-3 张角色参考图（JPEG/PNG格式，单张≤8MB，分辨率≥480p）。如不需要自定义角色，可回复"跳过"、"默认"或"不需要"，系统将使用智能匹配。"
   - 如果用户提供图片：遵循 `references/数字形象指南.md`，将校验通过的本地绝对路径或公网 URL 按顺序整理为 `--model-images` 的值（最多3张），不预先上传。
   - 如果用户回复"跳过"、"默认"、"不需要"等：不传 `--model-images`，系统使用智能匹配。
   无论用户选择哪种方式，完成后必须明确记录状态已流转至下一步。

5. **场景图片获取（可选，必须询问）**：向用户发送话术："是否需要提供场景/地点参考图？可上传 1-3 张场景参考图（JPEG/PNG格式，单张≤8MB，分辨率≥480p），用于控制视频的场景风格。如不需要，可回复"跳过"、"默认"或"不需要"。"
   - 如果用户提供图片：校验文件存在、绝对路径、JPEG/PNG 格式、单张 ≤8MB 和数量上限，将本地绝对路径或公网 URL 按原顺序整理为 `--location-images` 的值（最多3张），不预先上传。
   - 如果用户回复"跳过"、"默认"、"不需要"等：不传 `--location-images`。
   无论用户选择哪种方式，完成后必须明确记录状态已流转至下一步。

6. **创意提示词（可选，必须询问）**：向用户发送话术："是否有自定义的创意策略或爆点描述？可以告诉我您希望强调的卖点、风格倾向或创意方向（≤5000字符），我会用于指导视频生成的创意方向。如不需要，可回复"跳过"、"默认"或"不填"。"
   - 如果用户提供了提示词：设置 `--prompt`。
   - 如果用户回复"跳过"、"默认"、"不填"等：不传 `--prompt`。
   无论用户选择哪种方式，完成后必须明确记录状态已流转至下一步。

7. **字幕设置（可选，必须询问）**：向用户发送话术："是否需要在视频中添加硬字幕？\n① 添加字幕（默认）\n② 不添加字幕\n请回复序号；如不需要特别设置，可回复"默认"。"
   - 用户选择添加或回复"默认"：设置 `--nle-subtitle-enabled true`。
   - 用户选择不添加：设置 `--nle-subtitle-enabled false`。
   完成后，必须明确记录状态已流转至下一步。

8. **字幕擦除设置（可选，必须询问）**：向用户发送话术："是否需要开启字幕擦除功能？开启后会在分镜渲染阶段尝试擦除模型生成的字幕，但等待时间会较长。\n① 开启字幕擦除\n② 不开启（默认）\n请回复序号；如不需要特别设置，可回复"默认"或"跳过"。"
   - 用户选择开启：设置 `--use-subtitle-erasure true`。
   - 用户选择不开启或回复"默认"、"跳过"：设置 `--use-subtitle-erasure false`。
   完成后，必须明确记录状态已流转至下一步。

9. **AI 明水印设置（可选，必须询问）**：向用户发送话术："是否添加“AI生成”明水印？默认不添加。回复添加/不添加/默认即可。" 用户选择添加时设置 `--watermark true`，选择不添加或默认时设置 `--watermark false`。

10. **展示成片信息（强制不可跳过）**：在收集齐上述所有参数（包括必填和可选）后、准备正式提交任务之前，必须按照以下格式向用户展示即将生成的成片信息，询问用户是否符合预期。摘要必须包含参考视频和实际采用的商品信息：
   - 本地视频或图片仅展示文件名，不得展示绝对路径或目录。
   - 公网 URL 必须脱敏展示，至少保留域名和足以让用户辨识素材或商品的末尾片段；不得展示 URL 中的签名、token、鉴权参数或其他敏感查询参数。
   - 商品链接、商品 ID、商品图片可能同时存在时，逐项展示所有实际会传给 CLI 的值；商品图片需展示数量及按输入顺序排列的脱敏摘要。

> 🚨 **强制要求**：此步骤不可因为鉴权失败重试、参数调整、会话恢复或其他任何原因跳过。即使用户之前已确认过，每次提交新任务前都必须重新展示。

**播报模板示例（严格使用普通正文格式展示，保留换行，具体内容需从上文已收集的参数中提取填充）：**

- 角色图片：[自定义/智能匹配]
- 场景图片：[已提供/未提供]
- 字幕：[添加/不添加]
- 字幕擦除：[开启/关闭]

👉 请确认以上成片信息是否符合您的预期？

展示成片信息后，如果参考视频、商品信息、语言、角色图片、场景图片、创意提示词、字幕、字幕擦除、AI 明水印或其他提交参数发生任何变化，之前的成片信息确认和二次确认立即失效。必须使用最新参数重新执行第 10 步完整展示，并重新执行第 11 步取得二次确认，严禁沿用修改前的确认结果。

11. **二次确认与合规提示（强制不可跳过）**：当用户明确回复成片信息符合预期后，必须进行二次确认，明确告知扣费风险及合规要求。等待用户明确回复确认或同意后，才可进入提交任务（Phase 1）环节。

> 🚨 **强制要求**：此步骤不可因为鉴权失败重试、参数调整、会话恢复或其他任何原因跳过。即使用户之前已确认过，每次提交新任务前都必须重新进行二次确认。

发送该确认消息前必须检查：

- 链接检查通过且用户明确确认后，才能进入 Phase 1。

### Phase 1: 提交任务
用户确认生成后执行以下操作：
1. 读取 `references/CLI前置校验指南.md`，确认 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli` 可用且 OAuth 登录态有效；否则按前置指南完成登录或终止操作。
2. 首次调用或参数不确定时执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_viral_task_v2 --help`，根据 Phase 0 收集的信息构造 CLI 参数，不得猜测帮助中未声明的选项。
3. 参数映射原则：
   - 必填：`--ref-video`、`--language`，以及商品信息三选一（`--product-url` / `--product-id` / `--product-images`）。
   - 可选：`--template-id`、`--model-images`、`--location-images`、`--prompt`、`--nle-subtitle-enabled`、`--use-subtitle-erasure`、`--watermark`。
   - 商品来源为抖店或抖音链接时，将用户提供的原始链接传入 `--product-url`。链接是否关联可用商品属于服务端商品解析能力，提交前不根据域名、路径或页面外观推断。
   - 本地素材完成格式、大小、文件存在性和绝对路径校验后，通过对应 CLI 选项直接传入绝对路径，由 `submit_viral_task_v2` 自动上传并转换为 URL。公网 URL 可直接传入。
   - 多素材参数按命令 `--help` 声明的方式传入并保持用户提供顺序，每个路径或 URL 作为独立参数安全传递。
   - 布尔选项按 CLI `--help` 声明的形式传入，不得自行猜测开关语法。
   - 用户明确回复“跳过”或“不填”的可选参数不传；用户选择“默认”时按 CLI 默认行为处理。
4. 执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_viral_task_v2`。基础命令示例：

```bash
npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli submit_viral_task_v2 \
  --template-id 978755330 \
  --ref-video /absolute/path/to/ref.mp4 \
  --product-url https://example.com/item \
  --language zh
```

实际执行时仅传用户确认过的参数；路径、URL、提示词不得通过未经转义的 shell 字符串拼接。
5. 命令退出码为 `0` 时解析 stdout JSON，提取 `task_id`、`request_id`、`request_body` 和 `raw`，立即将任务 ID、请求 ID、任务类型、提交时间、会话 ID 和本次参数摘要保存到会话上下文。
6. `submit_viral_task_v2` 会创建付费异步任务，不保证幂等，**任何失败场景均禁止自动重试提交命令**。命令非零退出或未获得完整成功响应时，读取并脱敏 stdout/stderr，并按以下规则处理：

   - **能够证明请求未发送**：仅限本地参数校验失败、CLI 进程未成功启动、OAuth 前置校验失败等明确发生在网络请求前的错误。修复问题后不得直接提交，必须返回 Phase 0 第 10、11 步，重新展示全部成片信息并取得用户二次确认。
   - **无法确认请求是否已受理**：包括网络中断、请求超时、响应解析失败、响应落盘失败、进程异常退出，或任何不能证明请求未发送的情况。禁止再次执行提交命令；若输出中存在 `task_id`，按 `references/任务查询指南.md` 查询该任务；若仅存在 `request_id`，记录并反馈用户用于人工排查；两者均不存在时，明确告知用户任务状态未知和重复提交可能重复扣费，等待用户核实后再决定，不得擅自重提。
   - **服务端明确拒绝且未创建任务**：向用户说明错误码和修正方案。需要修改参数时返回 Phase 0 对应信息收集步骤，修改完成后重新执行第 10、11 步；即使参数未变化，再次提交前也必须重新展示全部成片信息并取得二次确认。
   - 只有 CLI 或接口明确提供并实际使用幂等键时，才能依据其契约安全重放；不得自行假设 `request_id` 具有幂等能力。

语种代号：`zh` 中文、`en` 英文、`en-us` 英语-美国、`pt-br` 巴西葡萄牙语、`ja` 日语、`es-mx` 西班牙语-墨西哥、`id` 印尼语、`ms` 马来语、`tl` 他加禄语。

### Phase 2: 提交后回复
`submit_viral_task_v2` 提交成功后会在 stdout JSON 中返回 `task_id`。使用以下模板回复用户：
```txt
✅ 爆款裂变任务已提交成功，任务ID:<任务ID>
⚠️ 任务正在后台执行中，您可以随时通过「查询进度」来获取最新状态~ 🦞
```

用户查询进度时必须读取 `references/任务查询指南.md` 并执行 `npm exec -y --package @volcengine/kickart-open-mcp@1.0.x kickart-open-cli query_task_v2 --task-id <ID> --source ad_variations --auto-publish true`。禁止在提交阶段主动轮询或直接请求 OpenAPI。

如果提交返回错误，需严格按照全局 `SKILL.md` 中的【错误处理规范】匹配对应错误码，并按照以下模板回复用户建议：
```txt
❌ 爆款裂变任务提交失败(任务ID:<任务ID>)
- 错误码:<返回的错误码>
- 处理建议:<匹配 SKILL.md 错误处理规范中的用户处理建议>
```
