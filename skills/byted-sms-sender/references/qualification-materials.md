# 资质申请向导

客户没有可用资质，或要求新建、填写、补充资质时，先读取
[qualification-display.md](qualification-display.md)，按宿主能力选择且只选择一个展示
适配器。非 MCP App 路径将 `qualification-wizard` 作为可持续读取结果的前台会话运行，
并打开仅监听 `127.0.0.1` 的本机页面。不要
要求客户把营业执照、身份证、姓名、手机号或身份证号发到对话，也不要从聊天附件读取。
向导运行期间必须保留并持续读取同一个前台会话；直接根据其中的
`QUALIFICATION_EXCHANGE` 和 `QUALIFICATION_FAILURE` 排查，不要要求客户复制字段、
重启向导或关闭页面。

## 页面流程

1. 向导先读取账号规则，每次只展示一个步骤：基础信息 → 企业信息 → 法人信息 →
   经办人信息 → 责任人信息 → 授权材料 → 最终预览。授权材料仅在他用资质时展示；
   如果账号规则不要求授权委托书，该步骤只需确认即可继续。法人身份信息独立成步但
   仍为选填，不占用经办人步骤，也不要求客户默认补充法人身份证号、手机号或图片。
2. 基础信息中的资质名称必填且不超过 20 个字；后续 OCR 不覆盖客户已填写的名称。
   营业证件中的法人姓名必填、可修改，并且是
   整份草稿的唯一法人姓名来源；修改后立即废弃原营业证件校验结果和不再匹配的法人补充信息。不要默认收集独立的
   法人身份证号、手机号或身份证图片；三者均选填。客户补充身份证图片时必须同时提供
   两面，补充身份证号或手机号时才校验对应格式。法人信息完全不填时不要发送
   `legalPerson`，由服务端使用营业证件上的法人姓名。法人选择居民身份证并填写身份证号
   时执行二要素校验，提交 `legalCheckTicket`。
3. 企业、经办人和责任人步骤提供明确的信息校验按钮，切换下一步前必须完成当前可见字段
   校验。校验票据由本机服务保存，不展示给客户。营业证件校验未通过时，页面明确提示
   将转人工审核并允许继续；经办人校验必须通过。填写责任人前先询问是否与经办人相同：
   相同时直接复用经办人文字、图片和校验结果并提交 `sameOperator=true`；不同时才收集
   责任人信息并校验。经办人、责任人的姓名和身份证号必填；身份证图片、手机号只在
   账号规则要求时必填。账号信息 `userType=smb` 且当前角色填写了手机号时，人员信息
   校验通过后还必须完成手机号验证码校验；责任人与经办人相同时复用经办人的验证码
   校验结果。发码和验码分别调用 `SendSmsVerifyCodeByMobile`、
   `CheckSmsVerifyCodeByMobile`；验证码输入满四位后自动触发校验，发码成功后按钮冷却
   60 秒并显示剩余秒数。验证码本身不得写入日志或最终资质提交参数。
4. 他用时授权方自动取营业证件名称，被授权方自动取
   `ListAllSmsProduct.businessName`，两者均不可手填。仅在账号返回
   `needOtherUseCheck=true` 后要求一张授权委托书。其他材料选填，最多五张，
   提交时映射为 `otherMaterials`、`fileType=6`。营业证件、授权委托书、其他材料或任一角色
   再次保存时，整体替换该部分旧值、递增
   草稿版本并废弃旧预览；营业证件、经办人或独立责任人再次确认后自动刷新该部分校验。
   营业证件法人姓名变化时清除不再匹配的法人补充信息；同经办人模式下
   修改经办人会同步更新责任人。用途改为自用时移除已保存的授权委托书。
5. 营业证件、身份证、授权委托书和其他材料均支持 JPG、JPEG、PNG，单张不大于 2 MB。
   营业证件图片是否必填由 `needBusinessCertificateImage` 决定；图片非必填时允许直接手填。
   身份证分别上传人像面和国徽面。页面提示复印件或黑白营业证件需加盖红色企业公章，
   彩色图片无需盖章。
6. 图片由本机进程通过 `GetMUploadParam` 获取平台临时 ImageX 凭证并上传，再调用
   `GetOCRLicenseForAgent`。OCR 回填的
   企业名称、信用代码、法人、有效期、个人姓名和身份证号都可修改；手机号由客户填写。
   有效期格式为 `YYYY-MM-DD`，例如 `2020-01-01`；长期归一化为 `2099-12-31`。
7. 每次资质网络调用都输出一条 `QUALIFICATION_EXCHANGE`，包含调用阶段、请求、响应、
   HTTP 状态、Request ID 和 Log ID；解析或校验失败时再输出一条
   `QUALIFICATION_FAILURE`，保留错误码和上述诊断标识。脚本统一掩码姓名、身份证号和
   手机号；图片、文件内容与地址、上传凭证、Authorization 和校验票据仅显示是否存在，
   不输出原值。Agent 直接根据这些事件排查，不要求客户另行共享表单。
8. 只有上述必需校验都已执行且仍对应当前草稿时，页面才自动生成最终预览。提交时复用页面
   校验取得的企业、法人、经办人和责任人票据；企业未通过自动校验时使用控制台约定的人工审核
   标识，责任人与经办人相同时两个角色使用同一张经办人票据。校验票据不返回页面或
   Agent。客户明确勾选确认后，只调用一次 `ApplySignatureIdentificationForAgent`。
9. 修改任何字段后，再次点击“确认并继续”会重新保存、校验并生成新预览。请求超时或响应无法解析时返回
   `qualification_submission_outcome_unknown`，不得自动重试；确定的校验失败留在页面
   供客户修改。
10. “放弃本次填写”在全部步骤中保持可见，只清除尚未提交的本地草稿；最终提交开始后
   禁用，避免把可能已经创建的线上申请误报为已取消。Skill 不把删除资质包装成取消或
   撤回申请；操作失败时允许客户在同一页面重试。
11. CLI 最终信封只返回取消、待审核、结果未知等状态，以及成功时的资质申请 ID、草稿
   版本、公开 Request ID 和 Log ID；详细排障信息使用前述事件。提交成功后继续查询审核
   状态，不要阻塞等待审核。
12. 页面保持心跳并报告用户活动。显式放弃、Agent 取消或提交完成时立即关闭本机服务；
   页面关闭超过宽限期、连接中断或长时间无操作时自动清除未提交草稿。MCP Server 常驻，
   但每个表单 flow 必须独立结束和回收。

表单业务与本机服务平台无关；MCP App、宿主网页预览和外部浏览器只是展示适配器。非
MCP App 环境必须能在同一台机器访问 loopback 地址。
