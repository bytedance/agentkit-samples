# 国内短信规则

## 授权

- 预览摘要仅对当前命令有效，不写入磁盘。
- 申请摘要必须覆盖所有实际提交字段。
- 单条发送摘要必须覆盖消息组、签名、模板、顺序固定的收件人、重复号码处理、
  模板变量、渲染内容摘要和预计短信条数。
- 群发启动摘要必须覆盖任务 ID、任务名、消息组、签名、模板、不可变文件 Key、
  本地 SHA-256、有效/无效/重复号码数、内容摘要和发送时间。
- 任一字段变化都会使授权失效。
- 单条发送必须针对展示的摘要取得明确授权。
- 群发启动必须收到完全一致的话术 `确认启动任务 <taskId>`。
- 写操作结果未知时，本次授权视为已消耗。

## 国内短信资源

- 签名长度为 2–25 个字符，通常建议不超过 12 个字符。
- API 入参中的签名不要包含外围签名括号。
- 只使用属于当前调用身份、已审核通过且可用的资质。
- 资源状态 `2` 表示拒绝；`3` 和 `5` 表示审核通过或免审。签名申请要求资质
  已审核通过。模板申请要求所选签名与消息组、短信类型关系有效；缺少冗余
  `usable` 字段可以接受，明确 `usable=false` 必须拒绝。
- 群发要求签名已审核并绑定目标消息组。只有查询结果已限定到目标消息组且签名
  已审核通过时，才允许缺少 `usable` 或资质 ID；明确
  `usable=false` 必须失败。返回资质 ID 时，重新查询该客户可见资质。
- 单条发送使用最小资源门禁：消息组状态必须为 `1`；签名状态为 `3`/`5`
  且绑定所选消息组；模板状态为 `3`/`5` 且按所选签名和消息组过滤。
  缺少签名 `usable`、资质 ID 或短信类型字段不导致失败；明确
  `usable=false` 必须失败。单条发送门禁不要查询资质或校验消息组行业。
- 单条发送、群发创建或群发启动前，立即重新查询相关资源。
- 模板变量必须与内容及执行值完全一致。

## 手机号与文件

- 接受中国大陆 11 位手机号，也可带 `+86` 前缀；比较前统一为 11 位。
- 输出时仅保留前三位和后四位，中间使用星号隐藏。
- 单条发送 Action 的数量限制以已验证的代理契约为准。
- 群发文件使用 `phone` 列及模板变量对应的列。
- CSV 无需第三方依赖即可使用；XLSX 必须有明确运行时依赖，禁止静默按 CSV
  解析。
- 官方群发上限为 1,000,000 个手机号和 50 MB。
- 不要持久化上传文件、预签名 URL 或授权摘要。

## 群发定时规则

- 群发任务仅支持通知类和营销类模板。
- 即使模板元数据不完整，也要拒绝验证码模板或验证码内容。
- 定时任务必须设置为未来时间，最远不超过一个月，并位于已验证的国内短信发送
  时段内，通常为 Asia/Shanghai 时区的 08:00–21:30。
- 不要假设账号存在特殊发送时段例外。
- 是否可取消取决于最新任务状态和服务端响应；临近发送时间时不要承诺一定能取消。

## 脱敏

- 完全移除 AK/SK 和 Authorization 值。
- 所有手机号都必须脱敏，包括错误信息中的手机号。
- 不要回显验证码或敏感模板变量。
- 短信内容可能含个人数据时，对其截断或替换。
- 从材料 URL、回调 URL 和预签名 URL 中移除查询参数及 fragment。
- 只允许客户可见字段。即使服务端意外返回，也要丢弃所有非客户可见字段。

## 重试与对账

- 查询操作可以对连接失败、HTTP 429、可重试 5xx，以及公开瞬时业务码
  `1015`/`1999` 执行最多两次、有上限的指数退避重试。
- 除非 Action 契约后续声明服务端幂等字段，否则写操作只发送一次。
- CLI 写调用仅在明确未创建子进程或明确在请求发出前失败时才能回退。CLI 超时、
  非结构化失败或发送状态不明时，不得通过其他鉴权路径重放。
- 请求发送后响应丢失时，返回 `outcome_unknown`。
- 签名和模板申请通过资源查询对账；存在安全唯一键时，短信发送通过发送日志
  对账；群发写操作通过任务详情对账。
- 不要根据模糊时间窗或内容匹配对账单条发送或群发创建。如果没有唯一 Message ID
  或 task ID，保留 `outcome_unknown`，再次写操作前重新生成预览。
- 证据不足时，绝不能猜测成功或失败。

## 查询预算

- 聚合分桶查询与发送日志页数之和，在查询重试前不得超过 120 次逻辑分析查询。
- 每个公开 Action 的 API 总限流为 50 QPS，单客户默认限制为 5 QPS。
  查询必须有界；限流额度不代表可以重放写操作。
