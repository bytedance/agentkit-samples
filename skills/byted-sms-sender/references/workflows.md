# 客户工作流

本文只描述编排顺序。字段、状态和错误契约按任务读取：

- 资质、签名、模板申请：[application-contracts.md](application-contracts.md)
- 模板匹配、发送、群发、分析：[delivery-contracts.md](delivery-contracts.md)

## 发送前补齐资源

1. 根据完整内容判断短信类型，再有限分页查询消息组和签名。内容只能判断类型，不能猜
   客户品牌或主体。
2. 只有一个合格签名时直接推荐；多个时用结构化选择，只展示签名和消息组；客户指定
   签名时只校验该签名。
3. 没有签名时进入签名申请：按用途推荐已审核、可用资质；多个时结构化选择，没有时
   打开资质向导。
4. 资质、签名或模板提交后说明正在审核并停止。恢复时重新查询，不复用旧状态。
5. 选定签名后做逐字节模板匹配；没有精确模板才进入模板申请。

## 资质申请

没有可用资质或客户要求创建、修改资质时，读取
[qualification-materials.md](qualification-materials.md)，只启动一种展示适配器。客户
在本机页面完成材料、校验、预览和提交；Agent 只接收掩码诊断及申请状态。

## 签名申请

1. 选择用途一致且审核通过的资质。
2. 获取全部可见消息组；客户指定子集时只用该子集，否则使用全部。
3. 收集签名文字、来源、用途和明确的短信类型，不让客户选择行业。
4. 生成包含消息组 ID、名称和数量的预览。
5. 默认全选时提交前重查全部消息组；指定子集时只验证子集仍存在。
6. 摘要一致后提交一次，返回申请单号，不阻塞等待审核。

## 模板申请

1. 查询签名与消息组关系，根据完整内容判断短信类型。
2. 查询各可用消息组在该类型下的行业；行业不一致时让客户选择。
3. 校验内容、变量、签名和消息组；固定模板保留明确空变量列表。
4. 生成预览，摘要一致后提交一次并返回模板 ID，不阻塞等待审核。

## 单条发送

1. 确定并验证消息组、签名和短信类型。
2. 执行 `match-template`，只接受内容、变量和资源关系完全一致的已审核模板。
3. 用显式模板 ID 执行 `send-preview`；不得隐式选模板。
4. 校验号码和变量，展示脱敏收件人及安全内容，取得当前摘要的明确授权。
5. `send-submit` 前重跑相同预检，只发送一次。
6. 返回 Message ID；需要时用 `send-status` 查回执。响应丢失时只按已知 Message ID
   对账，无法确定则返回 `outcome_unknown`。

## 群发任务

客户明确要求群发时，即使只有一个测试号码也使用本流程。

1. 拒绝验证码模板，确认消息组、签名、模板和短信类型完全兼容。
2. 获取 CSV 示例并校验冻结的本地表头、变量和数据。
3. 计算文件哈希，获取预签名 URL，上传后只保存不可变对象 Key。
4. `batch-create` 创建任务，不自动启动；保留 `taskId + subAccount` 和本地交接摘要。
5. 启动前查询任务详情并生成最新脱敏预览；要求客户回复
   `确认启动任务 <taskId>`。
6. 再次查询并比较摘要，只调用一次 `batch-launch-submit`。
7. 用任务详情查询进度；任务完成不等于逐条送达，送达只认发送日志。
8. 取消前查询最新状态并检查发送窗口。

## 数据分析

1. 要求显式 ISO 8601 `--start`、`--end`；无时区按 Asia/Shanghai，最长 90 天。
2. 使用 `analytics` 查询聚合统计；仅在需要消息级证据且指定消息组时增加
   `--include-logs`。
3. 聚合统计与消息日志不混算；手机号只用于日志过滤，不回显。
4. 展示分子、分母、百分比、来源字段和数据截止时间；字段缺失、计数矛盾或分页截断
   返回 `insufficient_data`。
