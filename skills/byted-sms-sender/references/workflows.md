# 客户工作流

## 签名申请

1. 查询可用资质；没有可用资质时停止流程，并引导客户登录火山引擎控制台，在
   “国内短信 > 资质管理”完成资质申请，待资质审核通过后再继续。
2. 查询全部可见消息组，并规范化签名文本。
3. 客户明确指定消息组子集时，只使用该子集；客户不确定或未指定时，选择当前
   可见的全部消息组。
4. 收集用途和短信类型。`source` 必须为 `1 = 公司`、`2 = App` 或
   `3 = 商标`。
5. 不要求客户选择行业。`GetSubAccountDetail` 可用于解释消息组的短信类型与
   计费行业映射，但行业不是签名申请门禁。
6. 生成包含消息组 ID、名称、数量和规范摘要的预览。
7. 默认全选时，提交前立即重新查询消息组；新增或减少任何消息组都必须废弃旧
   预览并重新生成。客户明确指定子集时，只验证所选消息组仍存在，其他消息组变化
   不会使预览失效。
8. 只有传入摘要仍匹配时才提交一次。
9. 返回公开申请单号，并说明如何查询审核状态。
10. 不要阻塞等待审核，也不要通过本 Skill 发起或代替客户提交资质申请。

## 模板申请

1. 查询已审核签名及当前消息组关系。
2. 根据完整短信内容判断短信类型：验证码使用 `CN_OTP`，交易/通知内容使用
   `CN_NTC`，推广内容使用 `CN_MKT`。
3. 对签名绑定的每个可用消息组调用 `GetSubAccountDetail`，读取所判断短信类型
   对应的 `channelTypeToIndustryConfig`。
4. 如果所有可用消息组对应同一行业，选择一个代表消息组；如果行业不同，展示
   客户可见行业选项，并询问客户使用哪个行业。普通客户通常使用通用行业，但不要
   覆盖已发现的明确差异。
5. 校验内容、变量、签名、消息组和国内规则。固定模板必须保留明确的空变量列表。
6. 生成完整、安全的预览与规范摘要。
7. 只有摘要仍匹配时才提交一次。
8. 服务端返回时，同时展示模板 ID 和二级模板 ID。
9. 通过查询获取审核状态，不要无限等待。

## 单条发送

1. 根据客户提供的完整短信内容判断短信类型。
2. 使用完整内容、规范化签名和所选消息组执行只读 `match-template`。只保留状态
   为 `3`/`5`，且解析后内容、短信类型和消息组关系完全一致的模板。按签名限定
   的查询可能不重复返回签名关系；如果返回单数 `signature` 或复数
   `signatures`，必须与目标签名一致。存在多个候选时稳定排序返回，不要猜选。
3. 为 `send-preview` 与 `send-submit` 显式传入选定模板 ID；两个命令都不得
   隐式选择模板。
4. 只重新查询本次发送必需资源：消息组状态 `1`；签名状态 `3`/`5` 及消息组
   关系（明确 `usable=false` 时拒绝）；模板状态 `3`/`5` 及签名、消息组
   过滤；解析后的内容与精确变量名。单条发送不要查询资质或校验消息组行业。
5. 校验国内手机号和精确模板变量。使用未脱敏输入生成规范摘要，但只展示脱敏
   收件人和安全内容。
6. 在当前会话针对该摘要取得明确授权。
7. 携带预览摘要执行。执行前重新运行相同预检并计算摘要，然后只发送一次 POST。
8. 返回 Message ID，回执需另行查询。
9. POST 响应丢失时不要重发。使用已知 Message ID 或范围足够窄的发送日志查询
   对账；无法对账时返回 `outcome_unknown`。

## 群发任务

1. 拒绝验证码模板。
2. 解析已审核的消息组、签名、模板、变量、模板名和短信类型。只有查询已限定到
   目标消息组、公开签名结果已审核且绑定该消息组时，才允许缺少签名
   `usable` 或资质 ID；明确 `usable=false` 必须拒绝。返回资质 ID 时，
   重新查询该公开资质。
3. 为目标消息组解析 `ListSecondTemplate` 记录。保留明确的空模板变量列表；
   按签名限定的查询允许省略冗余签名关系；缺少展示名时使用模板 ID 作为
   `templateName`。
4. 获取模板示例。响应可能是 `application/octet-stream` CSV 文件流；按照
   该模板校验冻结的本地 CSV 表头与数据行。
5. 对本地文件计算哈希，获取预签名 URL，上传后使用服务端返回的不可变对象 Key。
6. 使用 `SetBatchTask` 创建任务。创建过程禁止调用 `ConsentBatchTask`，
   也不代表授权发送。
7. 返回并在会话中保留 `taskId + subAccount`、文件摘要、号码统计和状态。
   已校验且等待授权的任务状态为 `2`。
8. 启动前按 `taskId + subAccount` 查询详情，并展示最新脱敏任务摘要。详情缺少
   本地文件摘要或预检统计时，通过启动参数传递创建阶段保留的交接信息。预览必须
   包含短信类型、文件 Key 指纹、文件/内容 SHA-256、号码统计和发送时间。
9. 要求客户回复 `确认启动任务 <taskId>`。
10. 再次查询详情，要求状态为 `2`，并比较规范摘要。
11. 只调用一次 `ConsentBatchTask`；响应丢失时通过任务详情对账。
12. 使用任务详情查询进度，不要依赖列表查找状态 `2`。
13. 取消前查询任务详情，并校验取消时间窗口。

## 数据分析

1. 必须显式提供 ISO 8601 格式的 `--start` 与 `--end`。没有时区偏移时按
   Asia/Shanghai 解释，并展示规范化 `[start, end)` 区间和不含尾端的数据
   截止时间。
2. 拒绝超过 90 天的窗口。使用 `total`、`hour` 或 `day` 分桶调用
   `ListTotalSendCountStatForAgent`；小时/天边界固定使用 Asia/Shanghai，
   查询次数必须有限。
3. 聚合 Action 结果属于提交级统计，发送日志属于消息级证据。除非文档明确说明
   两者分母一致，否则不要相减或合并。
4. 只使用客户可见过滤条件：消息组（`--sub-account`）、聚合统计短信类型
   （`--channel-type`）、签名、模板，以及发送日志手机号（`--mobile`）。
   日志只允许按 `subAccount`、`signature`、`template` 和 `time` 分组；
   `--dimension` 只对已获取的公开日志记录分组，不会让聚合 Action 返回维度行。
5. 只有传入 `--include-logs` 才调用 `ListSmsSendLogForAgent`，并且必须同时
   指定消息组。限制页大小和最大页数，稳定排序，按 Message ID 去重，同时返回
   `complete` 与 `truncated`。手机号只用于请求，不得出现在报告中。不要同时
   使用 `--channel-type` 与 `--include-logs`：日志 Action 没有短信类型过滤
   条件，两条分支的数据范围不同。`sendLogsMobileFilterApplied` 只描述日志
   分支，聚合趋势不受手机号过滤。
6. 分析账号全量日志时，先调用 `ListSubAccountForAgent`，再逐个显式查询客户
   可见消息组。不要推测隐藏消息组，也不要传入账号覆盖。
7. 展示提交与回执的分子、分母、来源字段、百分比、数据截止时间，以及成功、
   失败、未回执数量；服务端 `TotalSendCount` 单独展示。
8. 保留公开错误码原值。`RE:*` 使用官方
   [发送接口错误码](https://www.volcengine.com/docs/6361/173288?lang=zh)
   查询；`CR:*`、`CE:*`、`NE:*`、`SY:*`、`UN:*` 等回执错误码使用官方
   [发送状态错误码](https://www.volcengine.com/docs/6361/173291?lang=zh)
   查询。不要硬编码含义或推断内部原因。官方文档没有该码时，明确说明未找到公开
   解释，并建议客户携带客户可见 Message ID 联系支持。
9. 字段缺失、分母为零、回执数量不一致、Message ID 缺失或分页截断时，返回
   `insufficient_data`。
10. 丢弃完整手机号、内容、变量、账号、错误详情，以及所有非客户可见字段。
